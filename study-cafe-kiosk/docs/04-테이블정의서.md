# 스터디 카페 키오스크 시스템 - 테이블 정의서

## 1. 개요

본 문서는 스터디 카페 키오스크 시스템의 모든 테이블에 대한 상세 정의를 제공합니다.

**현재 구현**: TypeScript 인터페이스 + LocalStorage
**향후 구현**: 실제 데이터베이스 테이블

## 2. 테이블 목록

| 번호 | 테이블명 | 설명 | 현재 구현 여부 |
|-----|---------|------|--------------|
| 1 | users | 사용자 정보 | ✅ 구현 |
| 2 | seats | 좌석 정보 | ✅ 구현 |
| 3 | tickets | 이용권 정보 | ✅ 구현 |
| 4 | sessions | 이용 세션 정보 | ✅ 구현 |
| 5 | usage_history | 이용 내역 | ✅ 구현 |
| 6 | payments | 결제 정보 | ⚠️ 타입만 정의 |

## 3. 테이블 상세 정의

### 3.1 users (사용자)

#### 3.1.1 테이블 설명
시스템을 사용하는 사용자(일반 사용자 및 관리자) 정보를 저장합니다.

#### 3.1.2 TypeScript 인터페이스
```typescript
interface User {
  id: string;              // 사용자 고유 ID
  username: string;        // 사용자 이름
  email: string;           // 이메일 (로그인 ID)
  phone: string;           // 전화번호
  password: string;        // 비밀번호
  isAdmin: boolean;        // 관리자 여부
  createdAt: Date;         // 가입 일시
}
```

#### 3.1.3 컬럼 정의

| 컬럼명 | 한글명 | 데이터 타입 | 길이 | NULL | 기본값 | 제약조건 | 설명 |
|-------|-------|-----------|-----|------|-------|---------|------|
| id | 사용자ID | VARCHAR | 36 | NOT NULL | - | PK | UUID 형식의 고유 식별자 |
| username | 사용자명 | VARCHAR | 100 | NOT NULL | - | - | 사용자 이름 (한글/영문) |
| email | 이메일 | VARCHAR | 255 | NOT NULL | - | UNIQUE | 로그인 ID로 사용 |
| phone | 전화번호 | VARCHAR | 20 | NOT NULL | - | - | 연락처 (예: 010-1234-5678) |
| password | 비밀번호 | VARCHAR | 255 | NOT NULL | - | - | 해시화된 비밀번호 |
| isAdmin | 관리자여부 | BOOLEAN | - | NOT NULL | FALSE | - | TRUE: 관리자, FALSE: 일반 사용자 |
| createdAt | 가입일시 | TIMESTAMP | - | NOT NULL | NOW() | - | 회원가입 일시 |

#### 3.1.4 인덱스
- **PRIMARY KEY**: `id`
- **UNIQUE INDEX**: `idx_email` ON `email`
- **INDEX**: `idx_created_at` ON `created_at`

#### 3.1.5 비즈니스 규칙
1. 이메일은 중복 불가
2. 비밀번호는 bcrypt 해싱 (향후 백엔드 구현 시)
3. isAdmin이 TRUE인 사용자만 관리자 페이지 접근 가능
4. 회원 탈퇴 시 관련 세션 및 내역도 함께 삭제 (CASCADE)

#### 3.1.6 샘플 데이터
```json
[
  {
    "id": "1",
    "username": "admin",
    "email": "admin@studycafe.com",
    "phone": "010-1234-5678",
    "password": "admin123",
    "isAdmin": true,
    "createdAt": "2024-12-14T00:00:00Z"
  },
  {
    "id": "2",
    "username": "홍길동",
    "email": "hong@example.com",
    "phone": "010-9876-5432",
    "password": "user123",
    "isAdmin": false,
    "createdAt": "2024-12-14T00:00:00Z"
  }
]
```

### 3.2 seats (좌석)

#### 3.2.1 테이블 설명
스터디 카페의 좌석 정보 및 실시간 상태를 관리합니다.

#### 3.2.2 TypeScript 인터페이스
```typescript
interface Seat {
  id: string;              // 좌석 고유 ID
  number: number;          // 좌석 번호 (1-30)
  type: 'single' | 'double' | 'group';  // 좌석 타입
  status: 'available' | 'occupied' | 'reserved';  // 상태
  floor: number;           // 층수 (1 or 2)
}
```

#### 3.2.3 컬럼 정의

| 컬럼명 | 한글명 | 데이터 타입 | 길이 | NULL | 기본값 | 제약조건 | 설명 |
|-------|-------|-----------|-----|------|-------|---------|------|
| id | 좌석ID | VARCHAR | 36 | NOT NULL | - | PK | 좌석 고유 식별자 |
| number | 좌석번호 | INTEGER | - | NOT NULL | - | UNIQUE | 1-30 범위의 좌석 번호 |
| type | 좌석타입 | ENUM | - | NOT NULL | - | - | 'single', 'double', 'group' |
| status | 상태 | ENUM | - | NOT NULL | 'available' | - | 'available', 'occupied', 'reserved' |
| floor | 층수 | INTEGER | - | NOT NULL | - | - | 1 또는 2 |

#### 3.2.4 ENUM 값 정의

**type (좌석타입)**:
- `single`: 1인석 (1-20번)
- `double`: 2인석 (21-28번)
- `group`: 단체석 (29-30번)

**status (상태)**:
- `available`: 이용 가능
- `occupied`: 사용 중
- `reserved`: 예약됨 (향후 기능)

#### 3.2.5 인덱스
- **PRIMARY KEY**: `id`
- **UNIQUE INDEX**: `idx_number` ON `number`
- **INDEX**: `idx_status_floor` ON `status, floor`

#### 3.2.6 비즈니스 규칙
1. 총 좌석 수는 30석으로 고정
2. 좌석 번호별 타입 자동 할당:
   - 1-20번: single
   - 21-28번: double
   - 29-30번: group
3. 층별 좌석 분포:
   - 1층: 1-15번 (15석)
   - 2층: 16-30번 (15석)
4. 상태 전이 규칙:
   - available → occupied: 결제 완료 시
   - occupied → available: 퇴실 시

#### 3.2.7 초기화 데이터
```javascript
Array.from({ length: 30 }, (_, i) => ({
  id: `seat-${i + 1}`,
  number: i + 1,
  type: i < 20 ? 'single' : i < 28 ? 'double' : 'group',
  status: 'available',
  floor: Math.floor(i / 15) + 1,
}))
```

### 3.3 tickets (이용권)

#### 3.3.1 테이블 설명
스터디 카페에서 판매하는 이용권의 종류 및 가격 정보를 저장합니다.

#### 3.3.2 TypeScript 인터페이스
```typescript
interface Ticket {
  id: string;              // 이용권 고유 ID
  name: string;            // 이용권명
  type: 'hourly' | 'daily' | 'weekly' | 'monthly';  // 타입
  duration: number;        // 이용 시간 (분 단위)
  price: number;           // 가격 (원)
  description: string;     // 설명
}
```

#### 3.3.3 컬럼 정의

| 컬럼명 | 한글명 | 데이터 타입 | 길이 | NULL | 기본값 | 제약조건 | 설명 |
|-------|-------|-----------|-----|------|-------|---------|------|
| id | 이용권ID | VARCHAR | 36 | NOT NULL | - | PK | 이용권 고유 식별자 |
| name | 이용권명 | VARCHAR | 100 | NOT NULL | - | - | 이용권 이름 (예: 2시간 이용권) |
| type | 타입 | ENUM | - | NOT NULL | - | - | 'hourly', 'daily', 'weekly', 'monthly' |
| duration | 이용시간 | INTEGER | - | NOT NULL | - | CHECK > 0 | 이용 가능 시간 (분 단위) |
| price | 가격 | INTEGER | - | NOT NULL | - | CHECK > 0 | 판매 가격 (원) |
| description | 설명 | TEXT | - | NULL | - | - | 이용권 설명 |

#### 3.3.4 ENUM 값 정의

**type (타입)**:
- `hourly`: 시간권 (2시간, 4시간)
- `daily`: 일일권 (종일)
- `weekly`: 주간권
- `monthly`: 월간권

#### 3.3.5 인덱스
- **PRIMARY KEY**: `id`
- **INDEX**: `idx_type` ON `type`

#### 3.3.6 기본 데이터

| ID | 이용권명 | 타입 | 시간(분) | 가격(원) | 설명 |
|----|---------|------|---------|---------|------|
| ticket-1 | 2시간 이용권 | hourly | 120 | 4,000 | 2시간 자유롭게 이용 가능 |
| ticket-2 | 4시간 이용권 | hourly | 240 | 7,000 | 4시간 자유롭게 이용 가능 |
| ticket-3 | 종일 이용권 | daily | 720 | 15,000 | 12시간 자유롭게 이용 가능 |
| ticket-4 | 주간 이용권 | weekly | 10,080 | 80,000 | 1주일 무제한 이용 가능 |
| ticket-5 | 월간 이용권 | monthly | 43,200 | 250,000 | 1개월 무제한 이용 가능 |

#### 3.3.7 비즈니스 규칙
1. 이용권은 삭제 불가 (비활성화 컬럼 추가 필요 시)
2. 가격 및 시간은 양수여야 함
3. 이용권 타입에 따른 duration 권장값:
   - hourly: 120-480분
   - daily: 720분
   - weekly: 10,080분
   - monthly: 43,200분

### 3.4 sessions (이용 세션)

#### 3.4.1 테이블 설명
사용자의 현재 이용 중인 세션 정보를 관리합니다.

#### 3.4.2 TypeScript 인터페이스
```typescript
interface Session {
  id: string;              // 세션 고유 ID
  userId: string;          // 사용자 ID (FK)
  seatId: string;          // 좌석 ID (FK)
  ticketId: string;        // 이용권 ID (FK)
  startTime: Date;         // 시작 시간
  endTime: Date | null;    // 종료 시간
  remainingMinutes: number; // 남은 시간 (분)
  status: 'active' | 'completed' | 'expired';  // 상태
}
```

#### 3.4.3 컬럼 정의

| 컬럼명 | 한글명 | 데이터 타입 | 길이 | NULL | 기본값 | 제약조건 | 설명 |
|-------|-------|-----------|-----|------|-------|---------|------|
| id | 세션ID | VARCHAR | 36 | NOT NULL | - | PK | 세션 고유 식별자 |
| userId | 사용자ID | VARCHAR | 36 | NOT NULL | - | FK(users) | 사용자 외래키 |
| seatId | 좌석ID | VARCHAR | 36 | NOT NULL | - | FK(seats) | 좌석 외래키 |
| ticketId | 이용권ID | VARCHAR | 36 | NOT NULL | - | FK(tickets) | 이용권 외래키 |
| startTime | 시작시간 | TIMESTAMP | - | NOT NULL | - | - | 세션 시작 시간 |
| endTime | 종료시간 | TIMESTAMP | - | NULL | - | - | 세션 종료 시간 (NULL: 이용 중) |
| remainingMinutes | 남은시간 | INTEGER | - | NOT NULL | - | CHECK >= 0 | 남은 이용 시간 (분) |
| status | 상태 | ENUM | - | NOT NULL | 'active' | - | 'active', 'completed', 'expired' |

#### 3.4.4 ENUM 값 정의

**status (상태)**:
- `active`: 이용 중
- `completed`: 정상 종료
- `expired`: 시간 만료 (향후 타이머 기능)

#### 3.4.5 인덱스
- **PRIMARY KEY**: `id`
- **INDEX**: `idx_user_status` ON `userId, status`
- **INDEX**: `idx_seat_status` ON `seatId, status`
- **INDEX**: `idx_start_time` ON `startTime`

#### 3.4.6 외래키 제약조건
- `userId` → `users.id` (ON DELETE CASCADE)
- `seatId` → `seats.id` (ON DELETE RESTRICT)
- `ticketId` → `tickets.id` (ON DELETE RESTRICT)

#### 3.4.7 비즈니스 규칙
1. 한 사용자는 동시에 하나의 active 세션만 가능
2. endTime이 NULL이면 현재 이용 중
3. 퇴실 시:
   - endTime 기록
   - status를 'completed'로 변경
   - 좌석 status를 'available'로 변경
   - usage_history 생성
4. remainingMinutes가 0이 되면 status를 'expired'로 변경 (향후 기능)

#### 3.4.8 샘플 데이터
```json
{
  "id": "session-1702543200000",
  "userId": "2",
  "seatId": "seat-5",
  "ticketId": "ticket-1",
  "startTime": "2024-12-14T10:00:00Z",
  "endTime": null,
  "remainingMinutes": 120,
  "status": "active"
}
```

### 3.5 usage_history (이용 내역)

#### 3.5.1 테이블 설명
완료된 이용 세션의 기록을 저장하여 통계 및 내역 조회에 활용합니다.

#### 3.5.2 TypeScript 인터페이스
```typescript
interface UsageHistory {
  id: string;              // 내역 고유 ID
  userId: string;          // 사용자 ID (FK)
  seatNumber: number;      // 좌석 번호
  ticketName: string;      // 이용권명
  startTime: Date;         // 시작 시간
  endTime: Date;           // 종료 시간
  duration: number;        // 실제 이용 시간 (분)
  amount: number;          // 결제 금액 (원)
}
```

#### 3.5.3 컬럼 정의

| 컬럼명 | 한글명 | 데이터 타입 | 길이 | NULL | 기본값 | 제약조건 | 설명 |
|-------|-------|-----------|-----|------|-------|---------|------|
| id | 내역ID | VARCHAR | 36 | NOT NULL | - | PK | 내역 고유 식별자 |
| userId | 사용자ID | VARCHAR | 36 | NOT NULL | - | FK(users) | 사용자 외래키 |
| seatNumber | 좌석번호 | INTEGER | - | NOT NULL | - | - | 사용한 좌석 번호 (1-30) |
| ticketName | 이용권명 | VARCHAR | 100 | NOT NULL | - | - | 구매한 이용권 이름 |
| startTime | 시작시간 | TIMESTAMP | - | NOT NULL | - | - | 이용 시작 시간 |
| endTime | 종료시간 | TIMESTAMP | - | NOT NULL | - | - | 이용 종료 시간 |
| duration | 이용시간 | INTEGER | - | NOT NULL | - | CHECK > 0 | 실제 이용 시간 (분) |
| amount | 결제금액 | INTEGER | - | NOT NULL | - | CHECK > 0 | 결제한 금액 (원) |

#### 3.5.4 인덱스
- **PRIMARY KEY**: `id`
- **INDEX**: `idx_user_start` ON `userId, startTime DESC`
- **INDEX**: `idx_start_time` ON `startTime`

#### 3.5.5 외래키 제약조건
- `userId` → `users.id` (ON DELETE CASCADE)

#### 3.5.6 비즈니스 규칙
1. 세션 종료 시 자동 생성
2. 삭제 불가 (감사 추적용)
3. duration 계산: `(endTime - startTime) / 60000` (밀리초 → 분)
4. 통계 쿼리에 활용:
   - 일일/주간/월간 매출
   - 좌석별 이용률
   - 이용권별 판매 현황

#### 3.5.7 생성 로직
```typescript
// Session 종료 시
const endTime = new Date();
const duration = Math.floor(
  (endTime.getTime() - session.startTime.getTime()) / (1000 * 60)
);

const history: UsageHistory = {
  id: `history-${Date.now()}`,
  userId: session.userId,
  seatNumber: seat.number,
  ticketName: ticket.name,
  startTime: session.startTime,
  endTime,
  duration,
  amount: ticket.price,
};
```

#### 3.5.8 샘플 데이터
```json
{
  "id": "history-1702543200000",
  "userId": "2",
  "seatNumber": 5,
  "ticketName": "2시간 이용권",
  "startTime": "2024-12-14T10:00:00Z",
  "endTime": "2024-12-14T12:00:00Z",

}
```

### 3.6 payments (결제) ※ 향후 확장

#### 3.6.1 테이블 설명
결제 정보를 관리합니다. 현재 버전에서는 타입만 정의되어 있으며, 향후 실제 결제 시스템 연동 시 사용됩니다.

#### 3.6.2 TypeScript 인터페이스
```typescript
interface Payment {
  id: string;              // 결제 고유 ID
  userId: string;          // 사용자 ID (FK)
  ticketId: string;        // 이용권 ID (FK)
  amount: number;          // 결제 금액
  method: 'card' | 'cash' | 'transfer';  // 결제 수단
  status: 'pending' | 'completed' | 'failed';  // 상태
  createdAt: Date;         // 결제 일시
}
```

#### 3.6.3 컬럼 정의

| 컬럼명 | 한글명 | 데이터 타입 | 길이 | NULL | 기본값 | 제약조건 | 설명 |
|-------|-------|-----------|-----|------|-------|---------|------|
| id | 결제ID | VARCHAR | 36 | NOT NULL | - | PK | 결제 고유 식별자 |
| userId | 사용자ID | VARCHAR | 36 | NOT NULL | - | FK(users) | 사용자 외래키 |
| ticketId | 이용권ID | VARCHAR | 36 | NOT NULL | - | FK(tickets) | 이용권 외래키 |
| amount | 결제금액 | INTEGER | - | NOT NULL | - | CHECK > 0 | 결제 금액 (원) |
| method | 결제수단 | ENUM | - | NOT NULL | - | - | 'card', 'cash', 'transfer' |
| status | 상태 | ENUM | - | NOT NULL | 'pending' | - | 'pending', 'completed', 'failed' |
| createdAt | 결제일시 | TIMESTAMP | - | NOT NULL | NOW() | - | 결제 시도 시간 |

#### 3.6.4 ENUM 값 정의

**method (결제수단)**:
- `card`: 카드 결제
- `cash`: 현금 결제
- `transfer`: 간편 결제 (카카오페이, 토스 등)

**status (상태)**:
- `pending`: 결제 대기 중
- `completed`: 결제 완료
- `failed`: 결제 실패

#### 3.6.5 인덱스
- **PRIMARY KEY**: `id`
- **INDEX**: `idx_user_created` ON `userId, createdAt DESC`
- **INDEX**: `idx_status_created` ON `status, createdAt`

#### 3.6.6 외래키 제약조건
- `userId` → `users.id` (ON DELETE CASCADE)
- `ticketId` → `tickets.id` (ON DELETE RESTRICT)

#### 3.6.7 향후 확장 계획
1. PG사 연동 (토스페이먼츠, 아임포트 등)
2. 결제 취소/환불 기능
3. 결제 영수증 발행
4. 결제 내역 조회 및 통계

## 4. 테이블 간 관계 요약

### 4.1 관계도
```
users (1) ──────< (N) sessions (N) >────── (1) seats
   │                   │
   │                   │ (N)
   │                   │
   │                   ↓ (1)
   │                tickets
   │
   │ (1)
   │
   ↓ (N)
usage_history
```

### 4.2 관계 상세

| 부모 테이블 | 자식 테이블 | 관계 | 외래키 | 삭제 규칙 |
|-----------|-----------|------|-------|----------|
| users | sessions | 1:N | sessions.userId | CASCADE |
| users | usage_history | 1:N | usage_history.userId | CASCADE |
| seats | sessions | 1:N | sessions.seatId | RESTRICT |
| tickets | sessions | 1:N | sessions.ticketId | RESTRICT |
| users | payments | 1:N | payments.userId | CASCADE |
| tickets | payments | 1:N | payments.ticketId | RESTRICT |
